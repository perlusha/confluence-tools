# Дозаполнение колонок «Функциональный блок», «Лид», «Аналитик»

Скрипт: `Fill-MatrixExtraColumns.ps1`

Дозаполняет в готовой матрице согласования три колонки, идя по её собственным строкам:
ссылка в столбце «Наименование раздела» указывает на страницу-источник.

---

## Запуск

```powershell
$env:CONFLUENCE_URL = 'https://confluence.example.com'
$env:CONFLUENCE_PERSONAL_TOKEN = '<PAT>'

.\Fill-MatrixExtraColumns.ps1 -Target 123456789            # план
.\Fill-MatrixExtraColumns.ps1 -Target 123456789 -Apply     # запись
.\Fill-MatrixExtraColumns.ps1 -Target 123456789 -Limit 5   # только первые 5 строк
```

| параметр | смысл |
|---|---|
| `-Target` | страница матрицы (ID или URL) |
| `-Limit N` | обработать только первые N строк |
| `-Apply` | записать; без него — только план |
| `-Insecure` | не проверять TLS-сертификат |

---

## Откуда берутся данные

| колонка | источник | формат |
|---|---|---|
| Функциональный блок | строка `03. Функциональный блок` шапки — **пилюля** из набора `301 «Функц. блок Example»` | пилюля `status-handy` |
| Функциональная область | строка `04. Функциональные области` шапки — **пилюля** | пилюля `status-handy` |
| Лид | строка роли, чья подпись содержит **«лид»** | ссылка на человека `ri:user` |
| Аналитик | строка роли ровно **`Аналитик`** | ссылка на человека `ri:user` |
| Общий статус согласования | строка `08.01. Общий статус согласования` шапки — **пилюля** | пилюля `status-handy` |

Что откуда берётся, задаётся таблицей `$SPEC` в начале скрипта — чтобы добавить колонку,
достаточно дописать одну строку. Подпись колонки в матрице и подпись поля на странице могут
отличаться (например, «Функциональная область» в матрице и «04. Функциональные области»
на странице) — это два независимых поля описания.

**Про «Лид»:** подпись встречается в 11 вариантах — `Тимлид по блоку Закупки`, `ТимЛид блока
Продажи`, `ТимЛид НСИ`, `Лид по НСИ`, `Тимлид (продажи)` и т. п. Поиск по `%лид%`
**работает**: все варианты содержат «лид», ложных срабатываний в дереве нет.

**Про «Аналитик»:** берётся точное совпадение — в дереве есть и другие роли со словом
(«Руководитель группы аналитиков», «Финансовый аналитик»), их подхватывать не нужно.

Где данных нет — ячейка остаётся пустой (`<br />`).

---

## Идемпотентность

Пилюли **переиспользуются**: если в ячейке уже есть макрос, берётся его `id`, а статус
правится через API только при расхождении. Новый макрос создаётся лишь при отсутствии.

Сравнение ячеек — **по смыслу**, а не по разметке: Confluence нормализует
`<ri:user …></ri:user>` в самозакрывающийся `<ri:user … />`, и построчное сравнение
разметки давало бы «изменение» на каждом прогоне. Поэтому повторный запуск
должен показывать **0 изменений**.

---

## Проверено

Матрица 123456789 (120 строк):

| колонка | заполнено | пусто |
|---|---|---|
| Функциональный блок | 118 пилюль | 2 |
| Функциональная область | 53 пилюли | 67 |
| Лид | 105 ссылок | 15 |
| Аналитик | 89 ссылок | 31 |
| Общий статус согласования | 115 пилюль | 5 |
| пилюли согласующих (не трогались) | 477 | — |

Повторный прогон — 0 изменений.

**Перед записью разметка проверяется на корректность XML** — если сборка строки что-то
сломала, скрипт предупредит до обращения к Confluence (ключ `-DumpPath` сохранит собранное
в файл).
